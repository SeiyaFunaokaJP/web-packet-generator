# 07. 認証 / セキュリティ

Status: draft / 仕様 §2.6

## 認証

- 管理パスワードの設定手段: `--password` / 環境変数 / 設定ファイル / 初回アクセス時のセットアップ画面。
- 未設定の場合は localhost のみ bind し、警告を表示する。
- ハッシュは argon2id。セッションは Cookie (HttpOnly, SameSite=Strict)。ログイン失敗はレート制限。
- 複数ユーザ + 役割 (admin / operator / viewer): P1。
- API トークン (CLI・自動化用): P1。

## 通信路

- TLS: 自己署名の自動生成、または証明書指定 (`rustls`)。
- リバースプロキシ配置の手順をドキュメント化する。

## 送出の安全策

送出は危険操作のため、管理者設定で次を制限できる。

- 送出先インタフェースの許可リスト
- 最大レート上限
- 確認ダイアログ、監査ログ ([11-risks.md](11-risks.md) の「誤用」対策)

## Web 側の防御

CSRF 対策、CSP ヘッダ。依存関係は `cargo audit` / `cargo deny` を CI で実行する。

## 利用範囲

検証環境以外での使用は禁止であることを、ドキュメントと起動時表示で明記する ([10-docs.md](10-docs.md) 法的注意)。

## 未決事項 (Open questions)

- 初回セットアップ画面を「localhost からのアクセスのみ」に限定するか (初回乗っ取り対策)。
- ログイン失敗レート制限の閾値、ロックアウト方式。
- 役割ごとの権限マトリクス (viewer は統計のみ、operator は送出、admin は設定)。
- 監査ログの保存先 (SQLite / ファイル) と保持期間、改ざん耐性の要否。
- API トークンのスコープ・失効方式。
- 自己署名証明書の保存場所とローテーション。
- CSP と WASM (`wasm-unsafe-eval`) の両立方法。
