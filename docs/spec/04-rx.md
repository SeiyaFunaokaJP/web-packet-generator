# 04. 受信 / 検証 (wpg-rx)

Status: draft / 元: TODO.md §2.3 (v1 は最小)

## 機能

| 機能 | 優先度 | 内容 |
|---|---|---|
| 受信カウンタ | v1 | 送出と同一/別インタフェースの pps / bps、フィルタ一致数 |
| 簡易 BPF フィルタ | v1 | フィルタ一致カウント |
| 先頭 N パケット表示 | v1 | Hex / ツリー表示 (解析器は `wpg-core` を再利用) |
| シグネチャ照合 | P1 | 送出パケットに埋め込んだ magic + seq を照合し、ロス・順序逆転・遅延を概算 |
| pcapng 保存 | v1 | 本格的なキャプチャ保存は pcapng 出力までに限定 |

## シグネチャ (Proposal)

payload 内に `magic (固定長) | stream id | seq | tx timestamp` を埋め込む案。フィールド配置と長さは未確定。`counter` ジェネレータと `expr` で生成できる形にする。

## 非ゴール

Wireshark 相当の解析や長時間キャプチャ保存は扱わない (§0 非ゴール)。

## 未決事項 (Open questions)

- 受信バックエンドを送出と同じ種別 (afpacket/AF_XDP/DPDK) にするか、v1 は pcap/afpacket のみとするか。
- 遅延概算に使う時刻源 (ソフトウェアタイムスタンプ / ハードウェア) と精度の表記。
- BPF フィルタの Windows (Npcap) / macOS での構文差異への対応。
- 送出と受信を同一ホスト・別 NIC で行う場合の時刻同期の扱い。
- 受信画面で保持する N の既定値と上限、メモリ管理。
