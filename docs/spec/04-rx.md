# 04. 受信 / 検証 (wpg-rx)

Status: draft / 仕様 §2.3 (v1 は最小)

## 機能

| 機能 | 優先度 | 内容 |
|---|---|---|
| 受信カウンタ | v1 | 送出と同一/別インタフェースの pps / bps、フィルタ一致数 |
| 簡易 BPF フィルタ | v1 | フィルタ一致カウント |
| 先頭 N パケット表示 | v1 | Hex / ツリー表示 (解析器は `wpg-core` を再利用) |
| シグネチャ照合 | P1 | 送出パケットに埋め込んだ magic + seq を照合し、ロス・順序逆転・遅延を概算 |
| pcapng 保存 | v1 | 本格的なキャプチャ保存は pcapng 出力までに限定 |

## シグネチャ (実装済み、M9)

フレーム末尾 24 オクテットに `magic "WPG\x01" (4) | stream id (4) | seq (8) | tx timestamp ns (8)` (いずれもビッグエンディアン) を送出直前に書き込む (`wpg_core::signature`、`wpg-tx` の `JobConfig::signature`)。ジェネレータではなく送出エンジンで埋め込むのは、連番を複数ワーカーで通しにし、時刻を送出直前に取るため。ペイロード (または Ethernet パディング) に 24 オクテット以上ない場合は埋め込まず `unsigned` に数え、UDP / TCP / ICMP / ICMPv6 のチェックサムは差分更新する。受信側は末尾 92 オクテット内で magic を探す。利用者向けの説明は `docs/{ja,en}/src/operations/rx-verify.md`。

## 非ゴール

Wireshark 相当の解析や長時間キャプチャ保存は扱わない (§0 非ゴール)。

## 決定事項 (M9)

- 受信バックエンド: v1 は `afpacket` (Linux)、`pcap` (feature)、`pcapfile` (ファイル再生、NIC なしのテスト用)、`null`。AF_XDP / DPDK の受信は対象外。
- フィルタ: tcpdump 構文のサブセットをユーザ空間で評価する (全 OS・全バックエンドで同じ結果。カーネル BPF へのコンパイルはしない)。
- 時刻源: ソフトウェアタイムスタンプ (`afpacket` は受信直後の `SystemTime`、`pcap` は libpcap のヘッダ時刻)。遅延は送受信の時計が一致する場合のみ有効と明記。
- 保持する先頭 N: 既定 100、上限 10000 (API)。終了したキャプチャはサーバに 20 件まで残す。

## 未決事項 (Open questions)

- ハードウェアタイムスタンプ (`SO_TIMESTAMPING`) への対応。
- 高 pps 受信 (TPACKET_V3 RX リング、AF_XDP) の要否。
